What is going on

A database shows Suspect in Management Studio, or the error log says the database is in suspect mode. You cannot connect to it, and the program that depends on it is down.

Suspect means SQL Server started recovery on the database and could not finish.

What usually causes it

  • The data file or the transaction log was damaged by a crash, a power loss or a storage fault.
  • A data or log file is missing or was moved.
  • The disk filled up while the server was writing.
  • Antivirus or backup software locked a file the server needed.

What to do first

  1. Read the SQL Server error log. It usually names the file that caused the problem.
  2. Copy the MDF and LDF files before you change anything, and find your latest backup.
  3. If a good backup exists, restoring it is often the safest route.
  4. Do not run a repair with data loss allowed on your only copy. Send me a sample instead.

How I fix it

Questions people ask

Should I run DBCC CHECKDB with REPAIR_ALLOW_DATA_LOSS?

Not on your only copy. The option is named that for a reason, because it removes whatever it cannot fix. Copy the data and log files first.

Can a suspect database always be recovered?

No, and I will not pretend otherwise. If the damage is deep, some rows will not come back. The sample check is there so you hear that early.
