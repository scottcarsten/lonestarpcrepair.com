What is going on

Your site or program stops working and the log says Table is marked as crashed and should be repaired. You may also see error 1194 or error 145, or the longer version that ends with last repair failed. Until the table is fixed, every SELECT, INSERT and UPDATE on it fails.

This happens most often with MyISAM tables, on both MySQL and MariaDB.

What usually causes it

  • The server was killed or the machine lost power while a table was being written.
  • The disk filled up in the middle of a write.
  • The MySQL process was stopped by force instead of shut down cleanly.
  • A backup or copy tool read the table files while the server was still writing to them.

What to do first

  1. Stop writes to the database if you can.
  2. Copy the whole data directory before you touch anything, including the .frm, .MYD and .MYI files.
  3. Run REPAIR TABLE or myisamchk on the copy, not the original. A repair can drop rows it cannot read.
  4. If the repair fails or the table comes back short, send me a sample.

Questions people ask

Is it safe to run REPAIR TABLE?

Run it on a copy of the data directory first. REPAIR TABLE can discard rows it cannot read, and once they are gone from your only copy, they are gone.

What if the message says the last repair failed?

That means the server tried to repair the table on its own and could not. It is the point where a copy of the files and a careful manual recovery matter most.
