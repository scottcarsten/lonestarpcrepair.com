What is going on

You open an .mdb or .accdb file and Access stops with the message Unrecognized database format, often followed by the file name. Sometimes error 3343 shows up with it. Access cannot read the structure of the file, so it refuses to open it at all.

That does not mean the data is gone. The rows are often intact even when the front door is locked.

What usually causes it

  • The computer crashed, lost power or lost its network connection while the file was being written.
  • The data file sits in a shared folder and the connection dropped while someone was saving.
  • The file was made in a newer version or format of Access than the one trying to open it.
  • The file grew close to the two gigabyte size limit.
  • A sync or backup program touched the file while it was open.

What to do first

  1. Make a copy of the file and work only on the copy. Every failed attempt on the original can change it.
  2. Try Compact and Repair on the copy. It handles light damage.
  3. If that fails, try importing the tables into a new blank database.
  4. If neither works, send me a sample.

How I fix it

I read the tables straight out of the damaged file and rebuild them in a clean database. Tables come first, since that is where your data lives. Queries, forms and reports follow where I can recover them. A damaged VBA project can lock you out of a file with perfectly good tables inside, and I can usually get those tables out.

Questions people ask

Does unrecognized database format mean my data is lost?

Not usually. The message means Access cannot read the structure of the file. The rows in the tables can often still be read out of the damaged file.

Should I run Compact and Repair?

Run it on a copy, never on your only file. Compact and Repair can throw away what it cannot fix, so a copy keeps your options open.
